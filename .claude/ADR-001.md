# ADR-001: Crackers Modinst — architecture and MVP scope

- Status: Accepted
- Date: 2026-09-22
- Product name: **Crackers Modinst**
- Slug (binary, files, env vars, assets): `crackers-modinst`

## 1. Context

We need a plug-and-play desktop tool that installs curated modpacks for games from a public remote library.

- The end user downloads one executable, runs it, and follows a TUI menu.
- Nothing else is required on the user's machine: no Go, no Java, no manual steps beyond those listed here.
- Platforms: Windows and Linux (amd64). macOS is explicitly unsupported.
- MVP game: Valheim (Steam). On Linux only the Proton build is supported. Native Linux Valheim is out of scope and is simply not detected.
- Future game: Minecraft (official launcher only, all mod loaders: Fabric, Quilt, Forge, NeoForge). It is not in the MVP, but the MVP design must not block it (see §12).

### Assumptions (given, do not validate in code)
- The game is vanilla: no mod loader, no mods, no leftover mod files.
- The game (and on Linux, Steam) is not running during install or remove.
- The user has launched the game at least once before installing. On Proton this guarantees the Wine prefix exists.
- At most one modpack is installed per game at a time.
- A modpack is complete and self-contained: no dependencies, no conflicts, one version of the pack, one version of each mod.
- The remote is public HTTPS with no auth and no signing.

## 2. Decision summary

| Area | Decision |
|---|---|
| Language | Go ≥ 1.22, `CGO_ENABLED=0`, static binaries |
| UI | TUI: `github.com/charmbracelet/bubbletea` + `github.com/charmbracelet/huh` (+ `bubbles` spinner, `lipgloss`) |
| Remote | Static JSON files + mod files over HTTPS; fetched fresh on every start; no cache, no offline mode |
| Detection | Separate package; strategies in code (`steam` now), per-game rules in remote `games.json` (data only, never scripts) |
| Install engine | Copy files into the game dir; a marker file in the game dir records installed files and undo actions; no other local state |
| Game-specific steps | Hooks declared in the manifest; each returns undo actions stored in the marker |
| Self-update | `github.com/creativeprojects/go-selfupdate` from GitHub Releases |
| Release | GoReleaser; targets `windows/amd64`, `linux/amd64` |
| Pack authoring | Separate script/repo (out of scope for this ADR's implementation) |
| MVP actions | Detect, Install, Remove (Reinstall = Remove + Install). No verify/fix. |

## 3. Remote library

Base URL: compile-time constant `RemoteBaseURL` (placeholder `https://example.com/crackers-modinst/`). It can be overridden by the hidden flag `--remote <url>` or the env var `CRACKERS_MODINST_REMOTE` (for testing).

Layout:
```
<base>/games.json
<base>/index.json
<base>/packs/<pack-id>.json
<base>/files/...            (convention only; manifests hold full or relative URLs)
```

Rules:
- Relative URLs anywhere are resolved against `<base>`.
- HTTP client: 30 s connect/header timeout, no overall timeout for file downloads, `User-Agent: crackers-modinst/<version>`.
- Every JSON document has `schema_version` (integer). If it is greater than the version the app supports, show "Please update Crackers Modinst" and do not proceed. `games.json` and `index.json` also carry `min_app_version` (semver). If the app is older, force the update prompt.
- Unknown JSON fields are ignored (forward compatibility).

### 3.1 games.json (detection rules)
```json
{
  "schema_version": 1,
  "min_app_version": "0.1.0",
  "games": [
    {
      "id": "valheim",
      "name": "Valheim",
      "strategy": "steam",
      "steam": { "appid": 892970 },
      "not_found_hint": "On Linux, Valheim must run via Proton (Steam → Properties → Compatibility) and be launched once.",
      "builds": [
        { "id": "windows",      "os": "windows", "anchor": "valheim.exe", "files": "windows" },
        { "id": "linux_proton", "os": "linux",   "anchor": "valheim.exe", "files": "windows" }
      ]
    }
  ]
}
```
- `builds` are evaluated **in array order** for the current OS (`runtime.GOOS`). The first build whose anchor exists in the install dir wins. If none matches, the game is not detected. A native Linux Valheim install has no `valheim.exe`, so it is not detected.
- `anchor` is a path relative to the game install dir. The reference point for a game is its anchor file.
- `files` selects which platform file list of the manifest applies (§3.3).
- `not_found_hint` (optional) is shown on the "no games detected" screen.

### 3.2 index.json (pack catalog)
```json
{
  "schema_version": 1,
  "min_app_version": "0.1.0",
  "packs": [
    { "id": "valheim-friends", "game_id": "valheim", "name": "Friends pack",
      "description": "Short text shown in the TUI", "manifest": "packs/valheim-friends.json" }
  ]
}
```

### 3.3 Pack manifest (own format)
```json
{
  "schema_version": 1,
  "id": "valheim-friends",
  "game_id": "valheim",
  "name": "Friends pack",
  "version": "2026.09.22",
  "owned_dirs": ["BepInEx"],
  "files": {
    "common":  [ /* FileEntry */ ],
    "windows": [ /* FileEntry */ ],
    "linux":   [ /* FileEntry */ ]
  },
  "hooks": [
    { "type": "proton_dll_override", "builds": ["linux_proton"], "dll": "winhttp", "mode": "native,builtin" }
  ],
  "loader": null
}
```
FileEntry:
```json
{ "url": "files/BepInExPack_Valheim.zip", "sha256": "<hex>", "size": 1234567,
  "kind": "zip", "dest": "", "zip_root": "BepInExPack_Valheim/" }
{ "url": "files/SomeMod.dll", "sha256": "<hex>", "size": 45678,
  "kind": "file", "dest": "BepInEx/plugins/SomeMod.dll" }
```
Semantics:
- **Effective file list** = `common` + the list named by the detected build's `files` field. Missing lists are treated as empty. A pack with only `common` works on every build.
- The `linux` list exists for future native-Linux games. Valheim packs use only `common` and `windows`.
- `kind: "file"`: `dest` is the target **file** path relative to the game root.
- `kind: "zip"`: `dest` is the target **directory** relative to the game root (`""` = root).
  - Only entries under `zip_root` are extracted (optional; `""` = whole archive), with the `zip_root` prefix stripped.
  - Directory entries create directories; file entries are written.
- `sha256` and `size` are those of the **downloaded** object (the archive for zips).
- All paths use forward slashes and are converted with `filepath.FromSlash`.
- `owned_dirs`: directories relative to the game root that are deleted recursively on remove (this catches files mods create at runtime, e.g. `BepInEx/config`, logs, cache).
- `version`: informational only (displayed).
- `hooks`: run only if the detected build id is in `builds`. Unknown hook types cause the pack to be rejected with an error ("update Crackers Modinst").
- `loader`: reserved for Minecraft (§12). The MVP must accept `null` or absence and reject a non-null value with "not supported in this version".
- For Valheim, the pack itself contains BepInEx (e.g. Thunderstore `denikson-BepInExPack_Valheim`, extracted to the game root: `winhttp.dll`, `doorstop_config.ini`, `BepInEx/...`). The tool has no BepInEx-specific logic.

## 4. Detection

Package `internal/detect`. Interface:
```go
type Result struct {
    GameID     string
    BuildID    string            // e.g. "linux_proton"
    AnchorPath string            // absolute
    RootDir    string            // absolute game install dir (install target)
    Extra      map[string]string // strategy data, e.g. "steam_library", "steam_appid"
}
type Strategy interface {
    Name() string
    Detect(game GameDef) ([]Result, error) // usually 0 or 1 result
}
```
- Strategies are registered by name. A game whose `strategy` is unknown is skipped and logged (the app is too old for it).
- Only games that have at least one pack in `index.json` are detected and shown.
- Detection is stateless and runs on every start (and on "Detect again").

### 4.1 Steam strategy
1. **Steam root candidates** (all that exist, deduplicated by cleaned absolute path):
   - Windows:
     - Registry `HKCU\Software\Valve\Steam`, value `SteamPath`. It may use forward slashes, so clean it.
     - Fallback: `HKLM\SOFTWARE\WOW6432Node\Valve\Steam`, value `InstallPath`.
     - Use `golang.org/x/sys/windows/registry` in a `_windows.go` file with build tags.
   - Linux: `~/.local/share/Steam`, `~/.steam/steam`, `~/.steam/root`, `~/.var/app/com.valvesoftware.Steam/.local/share/Steam`. Resolve symlinks before deduplicating.
2. **Libraries:** parse `<root>/steamapps/libraryfolders.vdf` with `github.com/andygrunwald/vdf`.
   - Top key `libraryfolders` (match keys case-insensitively).
   - Each child is either a map containing `"path"` (new format) or a plain string path (old format). Support both.
   - Always include `<root>` itself as a library.
   - Unescape `\\` → `\` in paths if the parser does not do so (cover this with a test fixture).
3. **Per library,** read `<lib>/steamapps/appmanifest_<appid>.acf`. If present, read `AppState.installdir`. Then `RootDir = <lib>/steamapps/common/<installdir>`.
4. **Anchor:** evaluate the game's `builds` for `runtime.GOOS` in array order. The first build whose `RootDir/<anchor>` exists gives the result. If none exists, there is no result for that library.
5. **Extra:** `steam_library=<lib>`, `steam_appid=<appid>`.
6. Missing files or parse errors in one library are logged and that library is skipped; they are never fatal.

## 5. Install engine

Package `internal/engine`. The marker file in the game root is the only persisted state.

### 5.1 Marker: `<RootDir>/.crackers-modinst.json`
```json
{
  "schema_version": 1,
  "app_version": "0.1.0",
  "pack_id": "valheim-friends",
  "pack_name": "Friends pack",
  "pack_version": "2026.09.22",
  "manifest_sha256": "<hex of raw manifest bytes>",
  "build_id": "linux_proton",
  "installed_at": "2026-09-22T12:00:00Z",
  "files": ["winhttp.dll", "BepInEx/core/BepInEx.dll", "BepInEx/plugins/SomeMod.dll"],
  "dirs_created": ["BepInEx", "BepInEx/core", "BepInEx/plugins"],
  "owned_dirs": ["BepInEx"],
  "undo": [
    { "op": "wine_reg_restore", "file": "/abs/.../pfx/user.reg",
      "section": "Software\\\\Wine\\\\DllOverrides", "name": "winhttp", "previous": null }
  ]
}
```
- Paths in `files`, `dirs_created` and `owned_dirs` are relative to RootDir with forward slashes. Paths in `undo` are absolute.
- Status derived at runtime:
  - No marker: **Not installed**.
  - Marker whose `manifest_sha256` differs from the current remote manifest's hash: **Update available**.
  - Marker whose `pack_id` is not in the index: **Installed (pack no longer offered)**.
  - Otherwise: **Installed**.

### 5.2 Path safety (mandatory, applies to manifest `dest` and every zip entry)
Reject if any of these hold:
- The path is absolute.
- It contains a volume name.
- A `..` segment remains after cleaning.
- `filepath.Join(RootDir, p)` is not inside RootDir after `filepath.Clean`.

Reject symlink entries in zips. On rejection, abort the whole install before writing anything.

### 5.3 Install algorithm
1. **Pre-flight (writes nothing):**
   - Manifest `schema_version` and hook types must be known, and `loader` must be null.
   - All paths pass §5.2.
   - Every hook's `Validate()` passes. For `proton_dll_override`: `<steam_library>/steamapps/compatdata/<appid>/pfx/user.reg` exists. If it is not in the game's library, search all Steam libraries. If none is found, abort with "Launch the game once via Steam (Proton), close it, then retry."
2. **Existing marker:**
   - If a marker exists, run Remove (§5.4) first, after the user confirmed in the UI.
   - Reinstall and switching packs both follow this path.
3. **Download** every effective FileEntry into `os.MkdirTemp` (removed via `defer`).
   - Stream to disk while hashing. Verify `sha256` (and `size` if > 0). Mismatch aborts with an error naming the file.
   - Show progress per file.
4. **Plan** the full list of target files, including the expanded zip contents read from the downloaded archives.
   - The same target path twice in the plan is an error (pack bug).
   - If a target file already exists, abort ("file already exists: X"). This is a cheap guard against overwriting game files, not a vanilla check.
5. **Write** in plan order.
   - Create missing directories and record them in `dirs_created` (parents before children).
   - Write each file to `<target>.modinst-tmp`, then `os.Rename` it into place. Preserve zip file modes on Linux, falling back to 0644 (0755 when the zip marks it executable).
   - Keep an in-memory journal of everything written.
6. **Hooks:** run `Apply()` for each applicable hook in manifest order. Each returns undo actions, which are appended to the journal.
7. **Commit:** write the marker via tmp file + rename. It is written **last**; the marker existing means the install is complete.
8. **Rollback:** on any error in steps 5–7, delete the journaled files, run undo actions in reverse, remove the `dirs_created` that are empty (deepest first), then report the error. Rollback errors are logged and shown but do not mask the original error.

### 5.4 Remove algorithm
1. Read the marker. If it is missing or unreadable, report "nothing to remove" (or show the error).
2. Delete every path in `files`. Missing files are fine.
3. Delete every `owned_dirs` entry recursively (after §5.2 validation).
4. Run `undo` actions in reverse order. Failures are collected and shown, and the remaining steps continue.
5. Remove `dirs_created` deepest-first, only if empty.
6. Delete the marker **last**, and only if steps 2–5 had no errors. Otherwise keep it so the user can retry, and show the errors.

### 5.5 Hooks
```go
type Hook interface {
    Validate(ctx HookCtx) error
    Apply(ctx HookCtx) ([]UndoAction, error)
}
type UndoAction struct { Op string; /* op-specific fields, JSON-serialized into marker */ }
```
Undo ops are executed by a registry keyed by `Op`. The MVP includes exactly one hook and one undo op:

**`proton_dll_override`** (fields `dll`, `mode`), undo op `wine_reg_restore`.
- File: the Wine `user.reg` (text; header `WINE REGISTRY Version 2`; LF line endings; preserve them as found).
- The section header line looks like: `[Software\\Wine\\DllOverrides] 1726999999`. The backslashes appear doubled in the file, and the trailing token is a unix timestamp. An optional `#time=...` line may follow it.
- Value line: `"winhttp"="native,builtin"`.
- **Apply:**
  1. Back up the file to `user.reg.modinst-bak` (overwrite any old backup).
  2. Find the section. Match the header case-insensitively on the part inside the brackets.
  3. If the value exists, record its previous raw value and replace it. Otherwise record `previous: null` and insert the value line after the header (and after any `#time=` line).
  4. If the section is missing, append `\n[Software\\Wine\\DllOverrides] <unix-now>\n"<dll>"="<mode>"\n`.
  5. Write via tmp file + rename.
- **Undo:** if `previous` is null, delete the value line; otherwise restore it. Leave the section header in place (harmless).
- Implement it as a pure function on `[]byte` so it is unit-testable.

## 6. TUI flow

The title bar shows "Crackers Modinst vX.Y.Z".

1. **Startup:**
   - Self-update check (§7), non-blocking with a 5 s timeout. Failures are logged, not shown.
   - Fetch `games.json` and `index.json`. On failure, show an error screen with Retry / Quit.
2. **Detect:** run detection for games that have packs.
3. **Main menu:** one row per detected game showing its status (§5.1), plus "Detect again" and "Quit". If no games are detected, list the supported games from `games.json` with their `not_found_hint`, plus "Detect again" and "Quit".
4. **Game menu:**
   - Not installed: **Install pack** opens the pack list (for that game, with descriptions), then confirm, progress, result.
   - Installed or update available: **Remove pack** (confirm, progress, result) and **Reinstall / Update** (Remove then Install of the same pack, one confirmation).
   - Installing a *different* pack while one is installed: confirm "This will remove <current> first."
   - **Back**.
5. **Progress screen:** spinner, current step text, per-file download progress.
6. **Result screen:** success, or the full error text with the log path shown. It returns to the menu; it never exits on error.
7. **Keys:** arrows/enter, `esc` back, `q`/`ctrl+c` quit (disabled while writing files; show "please wait").
8. **Windows:** the app must work when double-clicked (conhost). Do not require a pre-existing terminal.

Hidden flags (not shown in the UI):
- `--remote <url>`
- `--no-update`
- `--detect-only`: prints detection results as JSON to stdout and exits.
- `--version`

## 7. Self-update
- Uses `creativeprojects/go-selfupdate` with the GitHub source. Repo slug is a constant (`OWNER/REPO` placeholder).
- Version is injected via `-ldflags "-X main.version=<semver>"`. A version of `dev` skips the update check.
- On startup, if a newer release exists (or `min_app_version` requires it), prompt: "Update Crackers Modinst to vX.Y.Z? (Yes/No)". If `min_app_version` is not met, "No" quits the app.
- Apply the update. On success, show "Updated — please restart Crackers Modinst", then exit. Re-exec is optional.
- Release assets are produced by GoReleaser, which also produces `checksums.txt` (go-selfupdate validates against it). Asset naming:
  - `crackers-modinst_<version>_windows_amd64.zip` containing `crackers-modinst.exe`
  - `crackers-modinst_<version>_linux_amd64.tar.gz` containing `crackers-modinst`

## 8. Logging and errors
- Log file: `os.TempDir()/crackers-modinst.log` (truncated at each start). Use `log/slog`, text handler.
- Log every download, every file write, every hook, and every error.
- Permission errors show: "Permission denied writing to <path>. On Windows try running as administrator." Do not auto-elevate.
- User-facing errors are plain sentences with the path or file involved.

## 10. Testing requirements
- Unit tests:
  - VDF parsing (new and old `libraryfolders` formats, escaped Windows paths)
  - ACF `installdir`
  - build selection order and the no-match case
  - path safety (including zip-slip, absolute paths, `..`, Windows volume names)
  - `user.reg` editing (existing section, missing section, existing value, undo round-trip byte-identical when `previous` is null and the section pre-existed)
- Engine integration tests:
  - `httptest.Server` serving a manifest plus files and zips, with a temp dir as a fake game root.
  - Assert: install produces the exact files and marker; remove restores the directory tree to its exact pre-install state.
  - Assert: an injected failure mid-install triggers rollback and leaves the tree untouched.
  - Assert: a hash mismatch aborts before writing.
- Fake Steam layout test for the Linux strategy (temp HOME), covering: Proton build detected; native-only install (no `valheim.exe`) not detected.
- `go vet` clean. `CGO_ENABLED=0 go build` succeeds for `windows/amd64` and `linux/amd64`.

## 11. Rejected alternatives
- **Local state DB or cache:** rejected; the marker in the game dir plus fresh remote fetches suffice.
- **Downloadable detection scripts (Lua/Starlark/JS):** rejected; with an unsigned public remote this would be remote code execution. Rules are data; new strategies ship via self-update.
- **Symlinks/hardlinks instead of copies:** rejected; symlinks need admin or developer mode on Windows.
- **Native Linux Valheim:** rejected; BepInEx there needs Steam launch options edited in `localconfig.vdf`, which is fragile. Proton only.
- **Existing formats (.mrpack, CurseForge):** rejected in favor of our own format (§3.3), which borrows the same ideas.
- **Verify/fix command:** deferred.
- **Dedicated server installs:** out of scope.

## 12. Future: Minecraft (design constraints already honored)
- Official launcher only. Detection strategy `minecraft`:
  - Anchor: `launcher_profiles.json` in `%APPDATA%\.minecraft`, `~/.minecraft`, or `~/.var/app/com.mojang.Minecraft/.minecraft`.
  - The user must have launched the launcher once.
- The install target is a per-pack folder `.minecraft/modpacks/<pack-id>/`, which is the marker's RootDir. Vanilla `.minecraft` content is never touched except:
  - `versions/<loader-version-id>/` (recorded as an undo op `remove_dir`)
  - one profile entry in `launcher_profiles.json` (undo op `remove_json_key`; edit as parsed JSON, back up first)
- Manifest `loader`: `{ "type": "fabric|quilt|forge|neoforge", "mc_version": "1.21.1", "version": "<loader version>" }`.
  - Fabric/Quilt: fetch the profile JSON from their meta API (`meta.fabricmc.net/v2/versions/loader/<mc>/<loader>/profile/json`; Quilt equivalent) and write `versions/<id>/<id>.json`. The launcher downloads the libraries.
  - Forge/NeoForge: run the installer jar with `--installClient` (NeoForge: `--install-client`) using the Java runtime the official launcher already downloaded. The location must be researched and verified (Windows `.minecraft/runtime` or the MS Store launcher's `LocalCache`). Fallback: download a JRE to temp. The installer also adds its own launcher profile; remove it via undo.
  - Then add our profile: `type: custom`, `lastVersionId`, `gameDir` = pack folder, `name`, `icon`.
- Detection returns an anchor path, not an exe path, and the marker's undo list is generic. Both already hold in the MVP.

## 13. Pack build script (separate deliverable, not part of this implementation)
- Input: a folder mirroring the game root (optionally split into `common/`, `windows/`, `linux/`) plus metadata (id, name, game_id, version, owned_dirs, hooks).
- Output: a manifest per §3.3 (hashes and sizes computed) plus the files to upload, and an updated `index.json` entry.
