# ADR-002: Crackers Modinst — as-built architecture (v0.1.0)

- Status: Accepted
- Date: 2026-09-22
- Amends: [ADR-001](ADR-001.md). ADR-001 records the original decision and MVP scope. This ADR documents the system as it was actually built, including every addition and deviation. Where the two differ, this ADR wins.
- Product name: **Crackers Modinst**
- Slug: `crackers-modinst`

## 1. Context

Crackers Modinst is a plug-and-play desktop tool: a player downloads one executable, runs it, picks a game and a modpack from a TUI menu, and the tool installs or removes that pack. Packs come from a public remote library that holds data only (JSON plus files); nothing downloaded is ever executed.

Scope as built:

- Platforms: Windows and Linux, amd64. macOS is unsupported.
- Game: Valheim via Steam. On Linux only the Proton build is supported; a native Linux install is not detected.
- One pack per game at a time. Actions: detect, install, remove, reinstall/update, and remove leftover mod files.
- Self-update from GitHub Releases.
- Pack authoring tool (`modinst-pack`) that turns a pack folder into library files.
- Live library: <https://github.com/Knurobroddy/modinst-packs>, served from `https://raw.githubusercontent.com/Knurobroddy/modinst-packs/main/`.

Assumptions carried over from ADR-001 and not validated in code: the game is not running during install or remove, and on Proton it has been launched once so its Wine prefix exists. The "vanilla game folder" assumption is relaxed by leftover handling (§8.3).

## 6. Remote library

### 6.1 Transport

- **Base URL:** `--remote <url>` flag, else the `CRACKERS_MODINST_REMOTE` env var, else `config.RemoteBaseURL` (`https://raw.githubusercontent.com/Knurobroddy/modinst-packs/main/`). A trailing `/` is added if missing. The base must be `http` or `https`; plain `http` is allowed for local testing.
- **Resolution:** every relative URL (manifest paths, file URLs) is resolved against the base. Absolute URLs are allowed (Thunderstore). Resolved URLs must be `http(s)`; `file://` and others are rejected.
- **HTTP client:** 30 s dial, 30 s TLS handshake, 30 s response header timeout; no overall timeout (large downloads). Redirects are followed (Thunderstore redirects to its CDN). `User-Agent: crackers-modinst/<version>`.
- **Retries:** network errors, HTTP 429 and 5xx are retried, 4 attempts in total, waiting 1 s, 2 s, 4 s (or `Retry-After`, capped at 30 s). Other 4xx fail at once. This was added after Thunderstore answered a burst of 13 package downloads with 500/502.
- JSON documents are capped at 32 MiB. Unknown JSON fields are ignored.

### 6.2 `games.json`

```json
{
  "schema_version": 1,
  "min_app_version": "0.1.0",
  "games": [
    {
      "id": "valheim",
      "name": "Valheim",
      "strategy": "steam",
      "steam": { "appid": 892970 },
      "not_found_hint": "On Linux, Valheim must run via Proton (Steam → Properties → Compatibility) and be launched once.",
      "builds": [
        { "id": "windows",      "os": "windows", "anchor": "valheim.exe", "files": "windows" },
        { "id": "linux_proton", "os": "linux",   "anchor": "valheim.exe", "files": "windows" }
      ]
    }
  ]
}
```

- `builds` are evaluated in array order for the current OS; the first whose `anchor` exists under the install dir (and is not a directory) wins. No match means not detected.
- `files` selects the manifest's platform list (§6.4).
- Only games that have at least one pack in `index.json` are detected and shown.
- A game with an unknown `strategy` is skipped and logged.

### 6.3 `index.json`

```json
{
  "schema_version": 1,
  "min_app_version": "0.1.0",
  "packs": [
    { "id": "valheim-client", "game_id": "valheim", "name": "Client",
      "description": "Shown in the pack list", "manifest": "packs/valheim-client.json" }
  ]
}
```

### 6.4 Pack manifest (`packs/<id>.json`)

```json
{
  "schema_version": 1,
  "id": "valheim-client",
  "game_id": "valheim",
  "name": "Client",
  "version": "2026.09.22",
  "owned_dirs": ["BepInEx"],
  "preserve": ["BepInEx/config"],
  "files": {
    "common":  [ /* FileEntry */ ],
    "windows": [ /* FileEntry */ ],
    "linux":   [ /* FileEntry */ ]
  },
  "hooks": [
    { "type": "proton_dll_override", "builds": ["linux_proton"], "dll": "winhttp", "mode": "native,builtin" }
  ],
  "loader": null
}
```

FileEntry: `{ "url", "sha256", "size", "kind": "file"|"zip", "dest", "zip_root" }`.

- **Effective file list** = `common` + the list named by the detected build's `files`. Missing lists are empty.
- `kind: "file"`: `dest` is the target file path. `kind: "zip"`: `dest` is the target directory (`""` = game root); only entries under `zip_root` are extracted, with the prefix stripped. A non-empty `zip_root` that matches nothing is an error.
- `sha256` (lower- or upper-case hex) and `size` (checked if > 0) describe the downloaded object.
- `owned_dirs`: folders deleted recursively on remove (catches runtime configs, logs, caches). They may not be the game root.
- `preserve` (optional): files or folders whose user-changed files survive a reinstall or update of the **same** pack (§8.2 step 7). Path-safe, not the root. Remove and switching to another pack still delete them. Added without a schema bump: older apps ignore unknown fields.
- `hooks`: run only for builds listed in `builds`. Unknown hook types reject the pack even if they would not apply ("please update Crackers Modinst").
- `loader`: must be absent or `null`; anything else is rejected ("not supported in this version").
- Unknown `kind` values reject the pack. The manifest's `id` and `game_id` must match its index entry.
- `version` is informational. "Update available" is decided by the SHA-256 of the raw manifest bytes (§8.8).

### 6.5 Versioning

- Every document has `schema_version`. Supported: games 1, index 1, manifest 1, marker 1. A higher value raises `UpdateRequiredError` ("Please update Crackers Modinst").
- `games.json` and `index.json` carry `min_app_version` (semver; `v` prefix, pre-release and build metadata handled). If the app is older, the update is forced (§11). `dev` builds skip this check.

### 6.6 Hosting

- **Chosen:** public GitHub repo, raw URLs. raw.githubusercontent.com serves `text/plain` with `Cache-Control: max-age=300`, so changes can take up to 5 minutes to show. Content-addressed file names (§13) keep a stale manifest and new files consistent. Git refuses files over 100 MB; such files would go to GitHub Releases and be referenced by absolute URL.
- **Thunderstore references:** mods use versioned URLs `https://thunderstore.io/package/download/<Author>/<Name>/<version>/`. The manifest's sha256 pins the exact bytes, so Thunderstore cannot change what gets installed; if a version is deleted there, installs of that pack fail until it is re-hosted or updated.
- **Rejected: Google Drive as the base.** Drive has no path-based URLs, so `games.json`/`index.json` cannot be found. It can host single files by absolute URL, but files over about 100 MB return an HTML virus-scan page and popular files hit quotas; installs would then fail on the checksum.

## 7. Detection

Interface as in ADR-001 §4 (`Result{GameID, BuildID, AnchorPath, RootDir, Extra}`, `Strategy{Name, Detect}`), with a `Registry` that runs strategies for games that have packs. Results are deduplicated by game and root dir (case-insensitive on Windows). Detection runs at start, on "Detect again" (which also refetches the library) and after every operation.

### 7.1 Steam strategy

1. **Roots.** Windows: `HKCU\Software\Valve\Steam\SteamPath` (forward slashes cleaned), then `HKLM\SOFTWARE\WOW6432Node\Valve\Steam\InstallPath`, in `steam_windows.go` (the only user of `golang.org/x/sys/windows/registry`; Linux builds do not link it, and CI checks this). Linux: `~/.local/share/Steam`, `~/.steam/steam`, `~/.steam/root`, `~/.var/app/com.valvesoftware.Steam/.local/share/Steam`. Candidates are made absolute, symlink-resolved and deduplicated; missing ones are ignored.
2. **Libraries.** Every root plus the entries of `<root>/steamapps/libraryfolders.vdf`, parsed with `andygrunwald/vdf` v1.1.0. The top key `libraryfolders` matches case-insensitively. Only numeric child keys are libraries (skips `TimeNextStatsReport`, `ContentStatsID`); a child is either a map with `path` (any case) or a plain string (old format). The parser itself unescapes `\\` to `\`, including UNC paths (verified by fixture), so no manual unescaping is done.
3. **App manifest.** `<lib>/steamapps/appmanifest_<appid>.acf` → `AppState.installdir` (case-insensitive keys). `installdir` must be a single path segment. `RootDir = <lib>/steamapps/common/<installdir>`.
4. **Build selection** as in §6.2.
5. **Extra:** `steam_library`, `steam_appid` and `steam_libraries` (all libraries, joined with the OS path-list separator; used by the Proton hook to find a prefix in another library).
6. Missing or broken files in one root or library are logged and skipped, never fatal.

Verified on the development machine: registry → `C:\Program Files (x86)\Steam` → Valheim `build_id: windows`.

## 8. Install engine (`internal/engine`)

### 8.1 Path safety (`pathsafe`)

Applied to every manifest `dest`, every zip entry, `owned_dirs`, `preserve`, and every path read back from the marker. The rules are the same on every OS:

- A backslash is treated as a path separator (so `..\x` inside a zip is caught on Linux too).
- Rejected: NUL bytes; absolute or rooted paths (`/x`, `\x`); volume names, including drive letters (`C:x`, `C:/x`) and UNC/device prefixes; any `:` (NTFS alternate streams); any `..` segment left after cleaning; a joined path outside the root.
- File targets, owned dirs and marker entries may not resolve to the root itself.
- Symlink entries anywhere in an archive reject the pack.
- While writing, an existing path component that is not a real directory (file, symlink, junction) fails the install.

Any violation aborts before anything is written.

### 8.2 Install order

1. **Pre-flight** (writes nothing): fetch the manifest and hash its raw bytes; check schema, loader, kinds, and that `id`/`game_id` match; validate `owned_dirs` and every `dest`; create all hooks (unknown type = reject); run `Validate()` for the applicable ones.
2. **Download and verify** every effective entry into `os.MkdirTemp` (deleted afterwards), streaming to disk while hashing. A size or sha256 mismatch aborts with an error naming the URL. Progress is reported per file (throttled to 100 ms).
3. **Plan:** expand zips (entries under `zip_root`, directory entries included) and validate every target. Errors: a target written twice (case-insensitive on Windows), a path that is both file and directory, or a file named like the marker or inside the staging folder.
4. **Stage the existing pack** if a marker exists (§8.10): its `owned_dirs`, `files` and then-empty `dirs_created` are renamed into `<root>/.crackers-modinst-old/`. Its marker stays in place; its hooks are not undone yet.
5. **Leftovers** (§8.3): stop with a list (the staged pack is moved back first), or delete them if the user confirmed.
6. **Write** in plan order: create missing directories (journaled in `dirs_created`, parents first); write each file to `<target>.modinst-tmp`, then rename it into place; journal each file and its SHA-256.
7. **Keep user files** (reinstall/update of the same pack only): for each staged file below a `preserve` entry, copy it back if the new pack does not ship it, or if the pack ships it but the staged file's SHA-256 differs from the marker's `file_sha256` (the user changed it). Unchanged shipped files keep the new version. Files copied back that the pack does not ship are journaled as pack files, so remove still deletes them.
8. **Undo the old pack's hooks** (its marker's `undo`, in reverse).
9. **Hooks:** `Apply()` in manifest order; their undo actions are journaled.
10. **Commit:** write the marker via tmp + rename, **last**. Then delete the staging folder.
11. **Rollback** on any error in steps 6–10 (§8.5), then move the staged pack back. The old pack is intact unless the failure came after step 8; then its files are back but its hook changes are gone, and the error says to reinstall it.

Deviation from ADR-001 §5.3, which removes the existing pack before downloading: here downloading and plan validation come first. Zip entries can only be checked after download, and ADR-001 §5.2 requires aborting before writing anything, so a failed download or an unsafe archive never uninstalls the current pack. The existing pack is staged instead of removed, so a declined leftovers prompt or a failed write does not lose it either.

### 8.3 Leftovers (addition)

If a pack's target files, or its `owned_dirs`, already exist after an installed pack was staged (or while no marker is present), those paths are **leftovers**, typically from an earlier manual mod install. An existing owned folder counts too, because an old `BepInEx/plugins` would otherwise keep loading stale mods next to the pack. Files under an existing owned folder are listed once, as the folder.

- `Install` returns `*LeftoversError{Root, Paths}` (folders end with `/`). Nothing has been written.
- With `InstallRequest.CleanLeftovers = true` (set by the UI only after confirmation), those paths are deleted (`RemoveAll`) and the install continues.
- `Engine.CleanLeftovers(ctx, req, progress)` runs pre-flight, download and plan (without hook validation), then deletes the leftovers and returns them, without installing. It refuses when a marker exists ("use Remove pack instead").
- Only paths the pack itself would write, plus its owned folders, are ever considered. Files unknown to the pack are never touched, and the code contains no game-specific list of mod files.
- Leftovers deleted this way are not restored by a later rollback or remove.

This replaces ADR-001's plain "file already exists" abort.

### 8.4 Zip extraction and file modes

- Entry names use `/`; a leading `./` is dropped.
- Linux: the archive's Unix permission bits are kept when present (creator Unix, owner-readable); otherwise 0644, or 0755 if any exec bit is set. `chmod` after writing bypasses the umask.
- Windows: always 0644, because a missing write bit would create a read-only file.

### 8.5 Rollback

Delete a half-written tmp file, delete journaled files in reverse, run journaled undo actions in reverse, remove journaled directories deepest first if empty. Rollback errors are logged and appended to the message ("Rollback also had errors: …") without hiding the original error, which stays reachable with `errors.Is`.

### 8.6 Remove

0. Recover an interrupted install (§8.10).
1. Read the marker. Missing → `ErrNothingToRemove`; unreadable → error, marker kept.
2. Delete every `files` entry (path-safety checked; missing is fine).
3. Delete every `owned_dirs` entry recursively (path-safety checked; never the root).
4. Run `undo` actions in reverse; failures are collected and the remaining steps continue.
5. Remove `dirs_created` deepest first, only if empty.
6. Delete the marker **last**, only if steps 2–5 had no errors. Otherwise keep it and report "remove incomplete; the marker was kept so you can retry".

### 8.7 Marker

`<root>/.crackers-modinst.json`, written with two-space indentation:

```json
{
  "schema_version": 1,
  "app_version": "0.1.0",
  "pack_id": "valheim-client",
  "pack_name": "Client",
  "pack_version": "2026.09.22",
  "manifest_sha256": "<hex of raw manifest bytes>",
  "build_id": "linux_proton",
  "installed_at": "2026-09-22T13:10:45Z",
  "files": ["winhttp.dll", "BepInEx/core/BepInEx.dll", "…"],
  "dirs_created": ["BepInEx", "BepInEx/core", "…"],
  "owned_dirs": ["BepInEx"],
  "file_sha256": { "winhttp.dll": "<hex>", "…": "…" },
  "undo": [
    { "op": "wine_reg_restore", "file": "/abs/…/pfx/user.reg",
      "section": "Software\\\\Wine\\\\DllOverrides", "name": "winhttp", "previous": null }
  ]
}
```

Paths in `files`, `dirs_created` and `owned_dirs` (and the keys of `file_sha256`, the SHA-256 of each file as the pack shipped it) are relative with `/`; paths in `undo` are absolute. `file_sha256` is optional (older markers lack it: every staged file then counts as changed and is kept). Empty lists are written as `[]`. Undo actions are stored as flat JSON objects (`op` plus op-specific fields) and executed by a registry keyed by `op`; an unknown `op` is an error ("please update").

### 8.8 Status

| Condition | Status (as shown) |
|---|---|
| No marker | `Not installed` |
| Marker unreadable or newer schema | `Unknown (marker unreadable)` |
| Marker's pack not in the index | `Installed (pack no longer offered): <name> <version>` |
| Remote manifest hash ≠ marker hash | `Update available: <name> <version>` |
| Manifest could not be fetched | `Installed: <name> <version> (could not check for updates)` |
| Otherwise | `Installed: <name> <version>` |

### 8.9 Errors

- Permission errors become "Permission denied writing to <path>. On Windows try running as administrator." There is no auto-elevation.
- Messages are plain sentences naming the file or URL involved.

### 8.10 Staging and interrupted installs

`<root>/.crackers-modinst-old/` holds the previous pack during an install: `files/` mirrors the game root, and a byte copy of the previous marker sits next to it. Restoring renames every staged file back (replacing what is there), recreates staged folders, and deletes the staging folder only if everything moved back; otherwise the error names the folder.

If the app dies mid-install, the next `Install` or `Remove` recovers first: if the current marker is byte-identical to the staged copy, the new pack was never committed and the staged pack is moved back; otherwise the new marker was written and the staging folder is deleted. (Identical markers mean an identical install, so moving the staged files back is harmless.)

## 9. Hooks (`internal/hooks`)

```go
type Hook interface {
    Validate(ctx HookCtx) error
    Apply(ctx HookCtx) ([]UndoAction, error)
}
```

`HookCtx` carries the game id, build id, root dir, detection `Extra` and logger. Registries: hook types `{proton_dll_override}`, undo ops `{wine_reg_restore}`.

### 9.1 `proton_dll_override` (fields `dll`, `mode`)

- `dll` must match `^[A-Za-z0-9_.*-]+$`, `mode` must match `^[a-z,]*$` (no quotes or newlines can reach `user.reg`).
- **Validate:** find `<lib>/steamapps/compatdata/<appid>/pfx/user.reg`, trying the game's library first and then every library in `steam_libraries`. Not found → "The Proton prefix for this game was not found (…). Launch the game once via Steam (Proton), close it, then retry."
- **Apply:** copy to `user.reg.modinst-bak` (overwriting), edit, write via tmp + rename keeping the file mode, and return a `wine_reg_restore` undo action.

### 9.2 `user.reg` editor (pure functions on `[]byte`)

- The section is given as written in the file: `Software\\Wine\\DllOverrides` (doubled backslashes). The header match on the text inside the brackets is case-insensitive; the trailing timestamp is ignored.
- `SetRegValue`: if the value exists (name matched case-insensitively, escapes respected), replace its right-hand side and return the previous raw text after `=` (e.g. `"builtin"` including quotes). Otherwise insert `"<dll>"="<mode>"` after the header and any following `#…` metadata lines (a superset of `#time=`). If the section is missing, append `<eol>[section] <unix-now><eol>"<dll>"="<mode>"<eol>`.
- `RestoreRegValue`: `previous == nil` deletes the value line; otherwise the raw previous value is restored (re-inserted if the line vanished). The section header stays.
- Line endings are detected (CRLF if present, else LF) and preserved; untouched lines stay byte-identical. Round trips are byte-identical (tested for LF and CRLF).
- **Undo when `user.reg` no longer exists** (the prefix was deleted): a logged no-op, so remove is not blocked forever. The `.modinst-bak` backup is kept as a safety net.

## 10. TUI (`internal/tui`)

### 10.1 Layout

- Full terminal, alternate screen. Content is centered horizontally and vertically; key help is on the last row.
- **Banner:** the "CRACKERS MODINST" ASCII art (CRACKERS in `#E8A33D`, MODINST in `#8B6CF6`), version below (`v0.1.0`, or `dev build`). The largest variant that fits is chosen per frame:
  1. one line (125 columns; needs a terminal at least 127 wide and enough rows),
  2. CRACKERS stacked above MODINST (about 70 columns, 14 rows; used by the default 120×30 Windows console),
  3. plain title `Crackers Modinst v0.1.0`.
- **Panel:** rounded border, at most 96 columns, padding 1×2; the huh forms and text are sized to its inner width and re-sized on terminal resize.

### 10.2 Flow

1. **Startup:** load `games.json` + `index.json` (2 min timeout) and, if enabled, the update check (5 s timeout) in parallel. The menu appears when both are done. Load errors → error screen with the log path and Retry/Quit. Update-check errors are only logged.
2. **Update prompt** (if a newer release exists): "Update Crackers Modinst to vX.Y.Z?" (Yes/No). If the library requires a newer app, the prompt says "Choosing No quits" and No quits. If an update is required but no release is found → error screen asking for a manual download.
3. **Detect** (spinner), including each game's status; for an installed pack the remote manifest is fetched (1 min timeout per game).
4. **Main menu:** one row per detected game (`Valheim — <status>`, plus the path if a game is found twice), "Detect again", "Quit". With no detections: "No supported games were detected", the supported games with their `not_found_hint`, then "Detect again"/"Quit".
5. **Game menu** (shows folder and status):
   - Not installed: **Install pack**, **Remove leftover mod files**, Back.
   - Installed / Update available: **Remove pack**, **Reinstall / Update**, **Install a different pack** (if more than one pack), Back.
   - Pack no longer offered: Remove pack, Install a different pack (if any), Back.
   - Marker unreadable: Remove pack (shows the error), Back.
6. **Pack list:** `Name — description`, `(installed)` on the current pack. It is used for installing and, with several packs, for choosing whose leftovers to remove.
7. **Confirmations** (Yes/No, default No):
   - Install: "Install <pack>?", plus "This will remove <current> first." when switching packs.
   - Reinstall: "Reinstall <pack>?"
   - Remove: "Remove <pack>?", noting that configs and logs in the pack's folders go too.
   - Leftover cleanup: explains that only the pack's own paths are deleted.
8. **Leftovers during install:** "Leftover mod files found. Delete them and install?" lists up to 8 paths (folders marked) and "… and N more". Yes reruns the install with `CleanLeftovers`; No returns to the game menu.
9. **Progress:** spinner, current step, per-file download line with progress bar and bytes.
10. **Result:** "Done." with details (e.g. the removed leftovers), or "Something went wrong." with the full error and the log path. Enter or Esc re-runs detection and returns to the menu. The tool never exits on an error.

### 10.3 Keys

Arrows and Enter to navigate, `esc` goes back (game menu → main, pack list → game menu, confirmation → previous screen, result → menu), `q`/`ctrl+c` quits. During an install, remove, cleanup or self-update, quitting is disabled for the whole operation (downloads included) and "Please wait" is shown. huh's own quit and filter keys are disabled.

### 10.4 Windows console

Works when double-clicked. Verified in legacy conhost at the default 120×30 size (stacked banner, full colors) and when launched through Explorer, which on Windows 11 opens Windows Terminal. Colors follow the environment (`NO_COLOR` disables them). On fatal startup errors the process waits for Enter on Windows, so the window does not vanish; `--detect-only` never waits.

## 11. Self-update (`internal/update`)

- **Enabled** unless the version is `dev` or `--no-update` is given. `GitHubRepo` is `Knurobroddy/crackers-tui`.
- **Check:** go-selfupdate `DetectLatest` with the GitHub source and a `ChecksumValidator{checksums.txt}`. It picks the newest non-draft, non-prerelease semver release that has an asset ending in `<os>_<arch>.zip`/`.tar.gz`, and offers it if newer than the running version.
- **Apply** (our own sequence rather than `UpdateTo`): download the asset and `checksums.txt` via the source, validate the SHA-256, extract the entry named after the canonical binary `crackers-modinst[.exe]` (not after the running file's name, so a browser-renamed `crackers-modinst (1).exe` still updates), then `update.Apply` onto the running executable. On Windows the old binary is moved to a hidden `.<exe>.old`; `CleanupOld()` deletes it on the next start.
- **After success:** "Updated — please restart Crackers Modinst", any key exits. A failed forced update offers Retry/Quit; a failed optional update shows the error and continues to the menu.
- **Verified:** asset matching for both OSes and checksum tampering with a fake release source (unit tests); replacing a *running* `.exe` on Windows, including a renamed one, by a manual test; real GoReleaser v2.18.2 snapshot output (names, single-binary archives, `checksums.txt` format). Not yet verified against a real GitHub release.

## 12. Command line and logging

Hidden flags: `--remote <url>`, `--no-update`, `--detect-only` (prints detection results for games with packs as JSON on stdout; exit 1 on error), `--version` (`crackers-modinst <version>`). The version comes from `-ldflags "-X main.version=<semver>"`, default `dev`.

The log file `os.TempDir()/crackers-modinst.log` is truncated at each start; `log/slog` text handler, debug level. It records startup parameters, every fetch and download (with retries), directory creation, file writes and deletions, hooks and undo actions, leftovers, rollback, operation start and end, and every error. go-selfupdate's own logging is routed into it. A top-level `recover` logs panics with their stack and prints a message; engine operations also recover panics and report them as errors on the result screen.

## 13. Pack authoring (`cmd/modinst-pack`, `internal/packer`)

Implements ADR-001 §13 inside the application repo, so it reuses the manifest types, path safety and the installer's plan validation.

### 13.1 Pack folder

```
<pack>/pack.modinst   metadata (JSON)
<pack>/common/        files for every build, mirroring the game root
<pack>/windows/       files only for builds whose "files" is "windows"
<pack>/linux/         files only for builds whose "files" is "linux"
```

Only these three folders are packed; other top-level entries (e.g. notes) are reported and skipped. `Thumbs.db`, `desktop.ini` and `.DS_Store` are never packed. Symlinks, special files and file names that `pathsafe` would change are rejected, as is a file named like the marker.

### 13.2 `pack.modinst`

```json
{
  "id": "valheim-client",
  "game_id": "valheim",
  "name": "Client",
  "description": "Shown in the pack list",
  "version": "2026.09.22",
  "owned_dirs": ["BepInEx"],
  "preserve": ["BepInEx/config"],
  "external": {
    "windows": [ { "url": "https://thunderstore.io/package/download/denikson/BepInExPack_Valheim/5.4.2350/",
                   "kind": "zip", "dest": "", "zip_root": "BepInExPack_Valheim/" } ],
    "common":  [ { "url": "https://thunderstore.io/package/download/ValheimModding/Jotunn/2.30.1/",
                   "kind": "zip", "dest": "BepInEx/plugins/ValheimModding-Jotunn", "zip_root": "plugins/" } ]
  },
  "hooks": [ { "type": "proton_dll_override", "builds": ["linux_proton"], "dll": "winhttp", "mode": "native,builtin" } ]
}
```

- Parsed strictly (unknown fields are errors). `id` must match `^[a-z0-9][a-z0-9._-]*$`; `game_id`, `name` and `version` are required.
- `owned_dirs` and `preserve` must be path-safe and not the root. Hooks must be known types with valid fields and a non-empty `builds`.
- `external` lists may only be `common`, `windows` or `linux`; entries need `url` and `kind` (plus `dest` for files). `sha256`/`size` are computed, or verified if given.

### 13.3 `build <pack-dir> <library-dir>`

1. Read and validate `pack.modinst`; check `game_id` against `<library>/games.json` (warning if that file is missing).
2. For each list: download every `external` entry (absolute `http(s)` only; HTML responses are rejected as login or confirmation pages) to compute its sha256 and size. Then zip the list folder **deterministically**: sorted entries, directory entries, fixed timestamp 2000-01-01, modes 0644/0755 (0755 only when the source has an exec bit), Deflate.
3. Name each zip `files/<id>-<list>-<first 12 hex of sha256>.zip` (content-addressed; an existing file with that name is not rewritten).
4. Validate every build combination (`common`, `common+windows`, `common+linux`) with `engine.ValidateFiles`, the installer's own plan check, plus `Manifest.Validate`.
5. Write `packs/<id>.json` (two-space indent, trailing newline) and upsert the pack's entry in `index.json`. Other packs and unknown fields are kept; a missing index is created with `schema_version: 1`, `min_app_version: "0.1.0"`.

Rebuilding unchanged input produces a byte-identical manifest, so players see no update.

### 13.4 `init <pack-dir>`

Writes a Valheim `pack.modinst` template (id and name from the folder name, today's date as the version, BepInExPack from Thunderstore, the Proton hook, `owned_dirs: ["BepInEx"]`, `preserve: ["BepInEx/config"]`) and an empty `common/BepInEx/plugins/`. Refuses to overwrite an existing `pack.modinst`.

### 13.5 From a mod-manager profile

The documented procedure (local `LOCAL_GUIDE.md` in the library repo) maps a Thunderstore Mod Manager/r2modman profile to a pack:

- Read `mods.yml` for packages and versions and build the versioned Thunderstore URLs.
- Choose `dest: BepInEx/plugins/<Author-Name>` with `zip_root` `""` (DLL at the zip root), `"plugins/"`, or the package's own folder, matching how the manager flattened the package.
- Put BepInExPack in the `windows` list.
- Copy the profile's `BepInEx/config` files except `BepInEx.cfg` (BepInExPack ships one, and BepInEx rewrites it on first launch) into `common/`, and strip secrets such as QuickConnect server passwords.

Verified against the real "Client" profile: every DLL, asset and config was identical after install. The differences were `BepInEx.cfg` (the pre-first-run copy), the password-less server list, and the manager's copies of package README/icon/manifest files, which the game never loads.

## 14. Build, release and CI

- **Local builds:** `CGO_ENABLED=0 GOOS={windows,linux} GOARCH=amd64 go build -trimpath -ldflags "-s -w -X main.version=<v>" ./cmd/crackers-modinst`.
- **`.goreleaser.yaml`** (v2): builds `./cmd/crackers-modinst` only; archives `tar.gz` with a zip override for Windows; name template `{{ .ProjectName }}_{{ .Version }}_{{ .Os }}_{{ .Arch }}`; `files: [none*]` so each archive holds only the binary; `checksums.txt` (sha256). `modinst-pack` is deliberately not released: a second archive per OS would make self-update's asset matching ambiguous.
- **`.github/workflows/ci.yml`:**
  - `test` job on `ubuntu-latest` and `windows-latest`: `go vet ./...`, `go test ./...`. On Linux it also cross-builds both static binaries and asserts that Linux builds do not import `windows/registry`.
  - `snapshot` job on every push to `main` and every pull request (not on tags): `goreleaser release --snapshot --clean`.
  - `release` job on `v*` tags: `goreleaser release --clean` with `contents: write`.
  - Actions used: `actions/checkout@v7`, `actions/setup-go@v7` (`go-version-file: go.mod`), `goreleaser/goreleaser-action@v7` (`version: "~> v2"`).
- **Release process:** tag `vX.Y.Z`, push the tag.
- `.gitattributes` in both repos keeps fixtures and library files byte-exact.

## 16. Deviations from and additions to ADR-001

| ADR-001 | As built | Reason |
|---|---|---|
| §5.3: remove existing pack, then download | Download, verify and plan first, then remove the existing pack | §5.2 requires aborting before any write on unsafe zip entries, which are only known after download |
| §5.3 step 4: existing target file → abort | Leftovers (existing targets and existing owned dirs) → confirm-to-delete, or abort; plus a standalone "Remove leftover mod files" | Folders dirty from manual installs blocked installs; stale plugins in `BepInEx/` would load next to the pack |
| §5.2 rule list | Stricter and OS-independent (backslash as separator, `:` and NUL rejected, drive letters on every OS) | Same result on every OS; catches Windows-style zip-slip on Linux |
| Suffixes `.crackers-tmp` / `.crackers-bak` | `.modinst-tmp` / `.modinst-bak`; new formats `.modinst` | Product decision |
| §3 HTTP client | Adds retries with backoff for network errors, 429 and 5xx | Thunderstore returns transient 500/502 under bursts |
| §4.1 Extra | Adds `steam_libraries` | The Proton prefix may live in another library |
| §6 title bar | Full-screen layout with ASCII banner (or plain title when small) | Product decision |
| §6 "Detect again" | Also refetches `games.json`/`index.json` | Avoids a stale catalog without restarting |
| §6 quit disabled while writing | Disabled for the whole operation, downloads included | Simpler and safer |
| §7 apply via go-selfupdate | Own apply sequence (download, checksum, extract by canonical name, `update.Apply`) plus `.old` cleanup; disabled for `dev` builds | Renamed downloads such as `crackers-modinst (1).exe` must update |
| §13 separate repo/script | `cmd/modinst-pack` in this repo | Reuses types, path safety and the installer's validation |
| §2 Go ≥ 1.22 | Go 1.26 | Required by the current `golang.org/x/sys` |
| §8 undo of `user.reg` | Missing `user.reg` at undo time is a no-op | A deleted prefix must not block remove forever |
| — | File `kind` must be `file` or `zip`; manifest `id`/`game_id` must match the index entry; pack may not contain the marker file | Reject pack bugs early |

## 17. Open items and known limitations

- **Repositories:** `GitHubRepo` is `Knurobroddy/crackers-tui` and the Go module path is `github.com/Knurobroddy/crackers-tui`. Renaming the application repo would cut released apps off from self-update. `RemoteBaseURL` is set to `https://raw.githubusercontent.com/Knurobroddy/modinst-packs/main/`. Renaming that repo or branch would cut every released app off from its library.
- Self-update has not been exercised against a real GitHub release.
- Packs cannot overwrite a file that another entry of the same pack provides. For example, a custom `BepInEx.cfg` next to Thunderstore's BepInExPack is rejected as "written twice".
- Configs live in the pack-owned `BepInEx/`, so a player's own config changes are reset on update, reinstall and remove.
- Packs that reference Thunderstore depend on those versions staying downloadable.
- raw.githubusercontent.com caches for about 5 minutes after a push; old `files/` must stay published for a while.
- Package metadata (README/icon/manifest.json) is not installed for packages extracted with `zip_root: "plugins/"`, which differs from the mod managers' layout but not in behavior.
- Native Linux Valheim, Minecraft (ADR-001 §12), dedicated servers, verify/fix and caching remain out of scope. The design constraints for Minecraft from ADR-001 §12 still hold: detection returns an anchor, the undo list is generic, and `loader` is reserved.
- Deleting a pack from the library is a manual step: remove `packs/<id>.json`, its `files/<id>-*.zip` and its `index.json` entry. `modinst-pack` has no `remove` command.

## 18. Consequences

- One static binary per OS, no runtime dependencies, no local state beyond the marker and a temp log.
- The remote is pure data with every byte pinned by SHA-256, so a compromised or changed host can at worst make installs fail, never execute code or write outside the game folder.
- Installs are all-or-nothing for everything the tool writes. Deleting leftovers is the one intentional, user-confirmed exception.
- Publishing a pack is: edit the sources, run `modinst-pack build`, test with `--remote` against a local server, push the library repo. The app needs no release for pack changes.
